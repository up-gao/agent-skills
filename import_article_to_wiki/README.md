# import_article_to_wiki

把 **微信公众号 / 掘金 / 今日头条 / InfoQ / CSDN / Anthropic** 的文章链接采集下来（图片本地化），
或把**已有本地 Markdown**，上传到**飞书知识库**。

**整条链路已全脚本化：一次 `python3` 调用搞定，不需要模型逐段写代码。**

## 一句话用法

```bash
python3 scripts/save_to_wiki.py --url "<文章链接>" --space <知识空间ID>
```

来源自动识别，无需指定平台。多篇就重复传 `--url`。

## 三个脚本

| 脚本 | 作用 |
|---|---|
| `save_to_wiki.py` | **编排入口**：识别来源 → 采集 → 路径规范化 → 发布 → 校验 → 汇总 |
| `fetch_wx_article.py` | 微信单篇采集：抓页 → 预处理 → 转 Markdown → 下载图片（含重试） |
| `download_images.py` | 下载 Markdown 中的图片并替换为相对路径 |

## 为什么需要它

上游技能的 SKILL.md 把多步（图片下载、路径替换、Markdown 组装）
写成了**要模型现场编写执行的代码块**。照那样做：

- 一次采集要十几轮模型往返
- 极易漏步 —— 已踩过：整步「图片下载」被漏掉，飞书文档里图全是空白

本技能把这些步骤固化成脚本，一条命令跑通。

| 坑 | 本技能的处理 |
|---|---|
| 微信图片**不会**自动下载（上游只给代码片段，没有脚本） | `fetch_wx_article.py` 内置下载 + 重试 |
| 掘金采集落盘的是**绝对路径**，飞书侧需要相对路径 | 统一转相对路径 |
| CSDN 自带的采集脚本默认写到自己技能的 `wk_data/csdn` | 调用时显式传 `--output-dir <workdir>` |
| Anthropic 采集脚本默认写到自己技能的 `wk_data/anthropic` | 调用时显式传 `--output-dir <workdir>` |
| 正文带 `# 标题`，飞书节点标题又有一遍，**标题重复** | 默认移除正文首个 H1 |
| 头条脚本无法从输出判断成败 | 用「工作目录是否新增 `.md`」判定 |
| 图片没下载成功却「发布成功」 | 统计远程残留图片，告警 + 退出码 1 |

## 主要参数

| 参数 | 说明 |
|---|---|
| `--url` | 文章链接，可重复传多篇 |
| `--md` | 已有本地 Markdown，跳过采集 |
| `--space` | 知识空间 ID，**新建**节点 |
| `--wiki` | 知识库**已有**文档链接，覆盖写入（会清空原内容） |
| `--parent-node` | 新节点挂到哪个父节点下 |
| `--title` | 标题（仅单篇有效，默认取 H1） |
| `--workdir` | 采集工作目录，默认 `/tmp/feishu-wiki-<时间戳>` |
| `--continue-on-error` | 某篇失败继续后续 |
| `--collect-only` | 只采集不发布 |

退出码：`0` 全成功；`1` 有失败或缺图；`2` 参数/依赖错误。

## 已知限制

- **CSDN 只支持 `blog.csdn.net/.../article/details/<id>` 形式的文章页**；专栏、用户主页未接入
- **掘金只支持单篇文章**（`/post/:id`）；专栏、用户主页未接入，需走 `fetch-juejin-knowledge` 手工流程
- **头条必须装 Playwright + Chromium**，否则拿不到正文
- 掘金批量采集图片耗时较长（20 张约 1-2 分钟），外层命令超时被截断时**重跑即可**
- `--wiki` 是覆盖写入，不可逆
- 写入较慢（逐块保顺序，145 段约 95 秒）
